# 2026 OceanBase 数据库大赛赛题

## 一、赛题背景与方向

考察**端侧推理 + SeekDB 检索**的综合工程能力

### 核心理念

所有推理在用户设备本地完成，**禁止调用任何云端推理 API**

### 支持的端侧运行时

- Transformers.js — 浏览器内运行🤗模型
- ONNX Runtime Web — 微软跨平台推理引擎
- TensorFlow.js — Google 机器学习框架
- MediaPipe — Google 多模态管线

### 初赛聚焦三大核心

1. **端侧量化向量化**：在浏览器端用量化模型将文本编码为向量
2. **SeekDB 检索建库**：向量与数据统一存入 SeekDB，建立知识库
3. **基础性能调优**：批处理、延迟优化、索引刷新策略

## 二、通用规则（6 条硬性规则）

1. **端侧运行**：模型推理（embedding 向量化）必须在浏览器 / 客户端本地完成
2. **必须使用 SeekDB**：向量 / 数据的存储与检索必须通过 SeekDB（seekdb-js 嵌入式或本地 server）
3. **模型开源**：自选模型，须为可公开获取的开源模型，并在文档中注明来源
4. **可访问交付**：提交可运行 Web 应用 + 完整源码 + 一页技术说明
5. **兼容性**：支持主流现代浏览器（Chrome / Edge 最新版），WebGPU 须处理降级
6. **禁止事项**：禁止预计算回放，禁止伪装端侧实则走远程

## 三、题目解析

**赛题：浏览器端「端侧向量化 + SeekDB 语义检索」迷你知识库**

### 完整流程

1. **用户导入语料**：支持文本文档（可选含图片）
2. **端侧向量化**：通过量化 embedding 模型完成编码
3. **写入 SeekDB**：存入向量 + 原文 + 元数据
4. **语义检索**：实现向量 + 全文混合检索

### 推荐端侧 embedding 模型

- all-MiniLM-L6-v2：~23MB (int8)・384 维
- bge-small-zh：~95MB (fp16)・512 维
- bge-small-en：~130MB (fp16)・384 维

> 
> 提示：模型自选，需能在端侧（浏览器）运行即可

## 四、任务要求（一）：端侧向量化・模型量化・后端降级

### 端侧向量化

- 使用 Transformers.js/ ONNX Runtime Web
- 在浏览器本地将文本编码为向量
- 不调用任何云端推理 API
- embedding 模型在客户端加载并执行

### 模型量化

- 对 embedding 模型进行 int8 或 fp16 量化
- 技术说明中给出量化前后体积压缩比与精度变化

### 量化参考基准

- fp32：100%
- int8：≈12%
- 体积压缩约 8 倍，质量无明显下降

## 五、任务要求（二）：后端降级・SeekDB 数据层・状态管理与调优

### 后端选择与降级

WebGPU 优先 → 不支持时自动降级 → WASM 降级 + 明确提示用户当前后端模式

### SeekDB 数据层

- 用 seekdb-js 创建集合 / 表
- 写入向量 + 原文 + 元数据
- 实现向量 + 全文的混合检索（非客户端拼合结果）
- 正确处理索引刷新

### 状态管理与基础调优

- 管理知识库的增量写入
- 管理集合 / 会话状态
- embedding 批处理优化
- 检索延迟优化
- 索引刷新策略优化

## 九、系统架构示意

整体分为三层：

1. **用户层・Browser / Web Client**
基于 Chrome / Edge 最新版浏览器，完成导入语料、发起检索操作
2. **端侧推理层・On-Device Inference**
包含 Transformers.js、量化模型 (int8/fp16)、WebGPU / WASM 执行环境、Embedding 向量化能力
3. **SeekDB 数据层・语义检索知识库**
提供向量存储、全文索引、混合检索、索引刷新能力
