# SeekVec 架构说明

> 正式赛题见 [`赛题.md`](赛题.md)。本文描述实现架构与关键数据流；性能与质量证据见 [`性能与质量报告.md`](性能与质量报告.md)，复现步骤见 [`复现.md`](复现.md)。

## 1. 三层职责

| 层 | 技术栈 | 职责 |
|---|---|---|
| 用户层（Browser / Web Client）| Vite + React 18 + Tailwind + Zustand | UI、拖拽导入、检索交互、集合/会话状态、性能观测与展示 |
| 端侧推理层（On-Device Inference）| Transformers.js + ONNX Runtime Web | embedding 模型加载与推理（WebGPU→WASM 自动降级、INT8/FP16/FP32 精度） |
| SeekDB 数据层 | Node.js + Express + seekdb-js | seekdb server（Docker / MSI）或嵌入式（Linux/macOS）；集合/文档/检索 API、计时、连接自愈 |

**合规约束**（正式赛题 2.2/2.5）：embedding 全程在浏览器内计算；server 不导入任何 onnx/transformers/default-embed 依赖，仅通过 HTTP 接收已算好的向量；存储与检索只走 seekdb。`npm run check:compliance` 可自动审计。

## 2. 进程拓扑与运行方式

```
npm run db:start（工作流脚本：检查/启动 docker compose seekdb，2882:2881，卷 /var/lib/seekdb）
npm run prepare:assets（fetch-ort → web/public/ort；fetch-models → web/public/models，均 gitignore）
npm run dev:docker
  → 读取根 .env（SEEKDB_*）→ predev check-seekdb → concurrently
       ├─ server (tsx watch, :3001)
       └─ web    (Vite dev, :5173，/api 代理 → 3001，COOP/COEP)
```

- Docker：`docker-compose.yml`（镜像 pin 说明、healthcheck、持久化卷）；MSI / 嵌入式模式见 README 与 [`复现.md`](复现.md)。
- 生产预览：`npm run build` 后 `web` 的 preview 同样带 `/api` 代理与 COOP/COEP（`web/vite.config.ts` 的 `preview.proxy`）。
- 版本兼容：seekdb-js 1.3.0 客户端 ↔ seekdb server 1.4.0（Docker）实测兼容；`/api/health` 返回真实 server 版本与 `refreshIndexSupported`。

## 3. 数据模型

| 集合 | 维度 | 索引 | 用途 |
|---|---|---|---|
| `kb_text_zh`（默认）| 512 | HNSW(cosine) + fulltext(ik, smart) | 中文文本 |
| `kb_text_en` | 384 | HNSW(cosine) + fulltext(ik, smart) | 英文文本 |
| `kb_image`（v1.1 预留）| 512 | 仅 HNSW | 图片（`IMAGE_PIPELINE_ENABLED=false`，未启用） |

- `embeddingFunction: null`：向量由 web 端写入；`schema.ts` 参数化 `dimension/modality/ikMode`。
- 文档级元数据：`source`（文件名）+ `chunkIndex`（块序号）；chunk id 为 `FNV-1a(source, chunkIndex, text)`，重复导入幂等。
- 集合已存在时会校验实际维度/模态与模型一致（409）；写入/检索前校验向量维度（400）。
- `GET /api/collections/:name` 返回真实 `describe()` + schema（HNSW/全文）信息，用于验收记录与排障。

## 4. 前端运行时

```
runtimeConfig(URL/localStorage)
  ├─ backend=auto|webgpu|wasm（强制项写 localStorage）
  ├─ dtype=q8|fp16|fp32（默认 webgpu→fp16、wasm→q8）
  ├─ batch=1..64（默认 32）、refresh=last|each、threads=1..8（隔离环境默认 8）
  ├─ models=auto|remote|local、perf=1、collection=<name>
  ▼
inference/runtime.ts（单例状态机，key=modelKey:backend:dtype）
  ├─ detectBackend() → {backend, preferred, forced, reason, adapterInfo}
  ├─ pipeline()（Transformers.js；revision 固定；progress_callback 拆分 model.download/model.init）
  ├─ generation 令牌：切模型/切后端丢弃过期加载，杜绝旧模型覆盖新状态
  └─ reload()/setForcedBackend()
  ▼
hooks（useEmbedding/useIngest/useSearch/useCollections）
  ├─ 分阶段计时（?perf=1 时记录到 perf/metrics.ts，环形缓冲 2000 条）
  ├─ activeCollection（persist）+ 集合下拉；无集合/维度不符时明确提示
  ├─ 导入：确定 ID → ensureCollection → 复用集合时一次取 id+source → 增量跳过未变块 → 仅对新增/变化 embedding（UTF-8 字节长度分桶）+ insert/upsert → 新建集合跳过清理，复用集合批量清理陈旧块 → 末批刷新（失败补偿）
  └─ 检索：query embed → /api/search（vector/hybrid）→ 结果按 metric 渲染
  ▼
perf/metrics.ts → window.__seekvecPerf（snapshot/summary/clear）
perf/evalApi.ts → window.__seekvecEval（ingestFiles/search/reset，仅 ?perf=1，供浏览器评测/复现）
```

**降级与错误语义**：`auto` 下 WebGPU 探测/初始化失败 → WASM 并显示原因；`?backend=webgpu|wasm` 强制模式下不静默降级（失败显示红色错误态，保证评测口径）；加载失败移除缓存并支持重试。

## 5. Server API

| 方法/路径 | 用途 | 关键响应字段 |
|---|---|---|
| `GET /api/health` | 就绪探针（`?deep=1` 打穿缓存）| `status`、`seekdb{reachable,latencyMs,version,refreshIndexSupported}` |
| `GET /api/collections` | 集合列表（刷新回填）| `collections[{name,modelKey,dimension,modality,count}]` |
| `GET /api/collections/:name` | 集合详情/schema | `dimension,distance,schema{hnsw,fulltext},count,timings` |
| `POST /api/collections` | 建集合/校验兼容 | `created,name,dimension` |
| `POST /api/collections/:name/refresh` | 手动刷新索引（维护/补偿）| `timings.refreshMs` |
| `DELETE /api/collections/:name` | 删除集合（维护/评测清理）| `ok,deleted` |
| `POST /api/documents` | 文本入库（`mode=insert|upsert`）| `mode,refreshed,timings{upsertMs,refreshMs,totalMs}` |
| `GET /api/documents?collectionName=&source=` | 按来源列 id（清理陈旧块）| `ids,count` |
| `DELETE /api/documents` | 按 ids/source 删除（维护）| `deleted` |
| `GET /api/documents/:name/count` | 条目计数 | `count` |
| `POST /api/search` | 纯向量/混合检索 | `mode,timings{resolveMs,dbMs,totalMs},knnK` + 原结果字段（distances 或 scores）|
| `POST /api/images` | 图片入库（v1.1 预留）| `ok,count` |

- 校验集中在 `routes/validation.ts`；错误统一 `{error, code?, requestId}`，400/404/409/503/500 语义明确；500 不泄漏 SQL。
- `POST /api/search` hybrid：显式传 `knn.nResults`，keyword 做 query_string 转义，并用 FIFO 互斥串行化 hybridSearch（规避 seekdb 会话变量 `@search_parm` 串味）；RRF 在库内完成，server 不做客户端拼合。
- `POST /api/documents`：`ensureCollection.created` 时前端用 `insert`（首批快速写入），其余用 `upsert`（幂等）；末批才 `refresh_index`。
- 连接自愈：seekdb 重启后首个请求自动重建连接并重试；查询超时 `SEEKDB_QUERY_TIMEOUT_MS` 透传。

## 6. 观测与评测链路

```
浏览器应用（?perf=1）                        Node 端（CI / 回归）
window.__seekvecPerf ──┐                      npm run test（server+web+scripts 单测）
window.__seekvecEval ──┤                      npm run eval:quality（标注集 Recall/nDCG/MRR）
                       ▼
scripts/bench-browser.mjs ──► docs/benchmarks/browser-*/raw.json + summary.md
scripts/bench-matrix.mjs  ──► docs/benchmarks/matrix-*/（ABBA、cold/warm、batch/refresh 消融）
scripts/eval-quality-browser.mjs ──► docs/benchmarks/quality-browser/
                       ▼
                docs/性能与质量报告.md（官方 3.2 表格 + 原始数据链接）
```

- 分阶段指标：`model.download`、`model.init`、`model.total`、`doc.read`、`doc.chunk`、`doc.embed`、`doc.write`、`index.refresh`、`ingest.total`、`query.embed`、`db.search`、`query.http`、`query.e2e`。
- 每次实验记录浏览器/GPU/Node/seekdb 版本、模型 revision+sha256、batch/refresh/后端/精度、语料与查询；≥5 次中位数 + IQR，冷/热分开。
- 质量门：q8/fp16 相对 fp32，Recall@5 降幅 ≤2pp、nDCG@10 降幅 ≤0.02。

## 7. 交付与可复现

- `docker-compose.yml` + `.env.example` + `web/.env.local.example`：一条命令起 seekdb，`dev:docker` 注入连接配置。
- `models.lock.json` + `scripts/fetch-models.mjs`：固定模型 revision/文件/sha256；`scripts/fetch-ort.mjs`：同源 ORT wasm。
- `scripts/acceptance.mjs`：环境/端口/健康/API/模型/合规逐项 PASS/FAIL。
- CI：install → build（server/web）→ 226 项单测（server 115 / web 69 / scripts 42）→ scripts typecheck → compliance；不依赖 seekdb/浏览器。
- 原始数据统一放 `docs/benchmarks/`（模型权重、浏览器 profile、缓存不入库）。

## 8. 版本边界

- **v1（首版提交）**：文本知识库，默认 bge-small-zh；中英模型切换；WebGPU 优先/WASM 降级；INT8/FP16/FP32 精度；导入幂等、陈旧块清理、索引刷新与补偿；刷新后集合回填；可观测与评测链路完整。
- **v1.1（stretch，未启用）**：图片管线（CLIP）。Schema/接口/模型注册已预留；CLIP 文本塔需 AutoProcessor + CLIPTextModelWithProjection，由 `IMAGE_PIPELINE_ENABLED=false` 保护。
