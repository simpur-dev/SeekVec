# SeekVec 架构说明

## 三层职责

| 层 | 技术栈 | 职责 |
|---|---|---|
| 用户层（Browser / Web Client）| Vite + React 18 + Tailwind | UI、拖拽导入、检索交互、集合/结果状态 |
| 端侧推理层（On-Device Inference）| Transformers.js + ONNX Runtime Web | embedding 模型加载与推理（WebGPU → WASM 降级） |
| SeekDB 数据层 | Node.js + Express + seekdb-js | seekdb server（Docker / MSI）或嵌入式（Linux/macOS）；集合管理、文档入库、混合检索 |

正式赛题 2.2（端侧推理）+ 2.5（禁止云端推理、禁止伪装端侧）：embedding 严格在浏览器端完成，server 禁止 import 任何 ONNX / embedding 库。

## 进程拓扑

```
npm run dev  →  predev (check-seekdb.mjs)  →  concurrently
                                              ├─ server/  (Node + tsx watch, http://localhost:3001)
                                              └─ web/     (Vite, http://localhost:5173)
                                                        │  /api/* 反向代理 → 3001
```

**SeekDB 运行模式（按环境选择）：**

| 环境 | 模式 | 说明 |
|---|---|---|
| Windows（推荐）| Docker `quay.io/oceanbase/seekdb` | 端口映射如 `-p 2882:2881`，数据卷必须挂容器内 `/var/lib/seekdb`；`SEEKDB_PORT=2882` 启动 dev |
| Windows | seekdb server MSI | 本机 `127.0.0.1:2881` |
| Linux/macOS | 嵌入式（SEEKDB_PATH） | 本地数据库文件 |
| Windows 嵌入式 | ❌ 不支持 | seekdb 官方标注 "Not supported yet" |

> 版本兼容：项目依赖 seekdb-js **1.3.0**；实测 1.3.0 SDK 与 seekdb server **1.4.0**（Docker 镜像）在集合/写入/混合检索/刷新索引上均兼容。

## 双集合设计

| 集合 | 维度 | Modality | 全量索引 | 用途 |
|---|---|---|---|---|
| `kb_text_zh`（默认）| 512 | text | ik smart | 中文文本 |
| `kb_text_en` | 384 | text | ik smart | 英文文本 |
| `kb_image`（v1.1）| 512 | image | — | 图片（当前开关关闭） |

- 文本集合：`VectorIndexConfig(HNSW, cosine) + FulltextIndexConfig(ik_mode)`
- `embeddingFunction: null`：向量由 web 端推理后经 HTTP 写入
- 集合已存在时会校验「实际维度/模态」与请求模型是否一致，不一致返回 409
- 列表接口 `GET /api/collections` 供前端刷新后恢复集合清单（SDK 需 `withEmbeddingFunction:false` 才能列出集合）

## 数据流

### 入库（文本）

1. `IngestPanel` 触发 `useIngestText.ingestFiles(files, collectionName)`
2. `readTextFile` → `chunkText`（256 字符 / 32 overlap / 最短 10）
3. chunk id = `FNV-1a(文件名 + 块序号 + 文本)`，**确定性 ID**，同文件重复导入得到相同 id
4. `POST /api/collections`（已存在则做维度校验）→ server 返回真实 `dimension`
5. 端侧 embedding 批处理（16 条/批）→ `POST /api/documents`（server 端 `upsert`）
6. 索引刷新：中间批次 `refreshIndex=false`，**最后一批统一 refresh_index**
7. 返回 `count` 写回 `kbStore`，供 StatsBar 展示

### 检索

1. `SearchPanel` 触发 `useSearch.searchAll(query, keyword, topK)`
2. 页面启动时 `useCollections` 已通过 `GET /api/collections` 回填 kbStore（刷新后仍可检索）
3. 文本管线：`embed([query], 端侧耗时)` → `POST /api/search`：
   - 有关键字：`collection.hybridSearch({ query: { whereDocument: { $contains } }, knn })`，RRF 在 **SeekDB 库内**完成，返回 `scores`（越大越相关）
   - 无关键字：`collection.query({ queryEmbeddings })`，返回 `distances`（cosine，越小越相关）
4. 图片管线（v1.1）：由 `IMAGE_PIPELINE_ENABLED=false` 保护，**当前不加载 CLIP、不发请求**
5. UI 按 `metric` 分别展示：纯向量显示相似度百分比，混合检索显示 `RRF 融合分`

## 状态管理（4 个 zustand store）

| Store | 内容 |
|---|---|
| `modelStore` | 当前模型 key 与维度（切模型时 UI 同步集合名、清空旧结果）|
| `backendStore` | 当前后端、降级原因、模型加载耗时 |
| `kbStore` | 集合清单、文档计数、ingest 进度（启动时由 server 回填）|
| `searchStore` | query/keyword、文本/图片结果、错误 |

## 质量保障

- `npm test`：纯逻辑单元测试（server：Schema 构建 / 错误状态映射 / 连接错误识别；web：分块边界 / 确定性 chunk id / 检索响应解析）
- `.github/workflows/ci.yml`：push / PR 时安装依赖、类型检查 + 构建两端、运行单测
- `npm run probe`：依赖真实 seekdb 的端到端探针；`npm run bench`：量化一致性评测

## 降级与容错

1. **启动探测**：`detectBackend()` 检查 `navigator.gpu` 并请求 adapter
2. **运行时失败**：`loadModelWithFallback` 在 pipeline 初始化失败时切 WASM；模型缓存键为 `modelKey:backend`，失败 Promise 会从缓存移除，保证重试可用
3. **UI 提示**：`BackendBadge` 显示 WebGPU / WASM + 降级原因 + 模型加载耗时；模型加载失败时导入/检索面板出现「重试」
4. **数据侧防护**：集合维度不匹配 409、向量维度不匹配 400、集合不存在 404
5. **连接自愈**：seekdb 重启后 server 首次请求会自动重建连接并重试（无需重启 dev）
6. **WASM 多线程**：dev 与 preview 均注入 COOP/COEP；ORT wasm 可用 `VITE_ORT_WASM_PATH` 指向本地托管

## 版本边界

- **v1（首版提交）**：文本管线，默认 bge-small-zh，中英模型切换，bench 评测，导入幂等、错误可重试、刷新后检索可用
- **v1.1（stretch）**：图片集合（CLIP 视觉塔 + 文本塔）。文本塔需 `AutoProcessor + CLIPTextModelWithProjection`，当前由 `IMAGE_PIPELINE_ENABLED=false` 关闭，避免误触发大模型下载
