# 复现指南

> 本文覆盖 **从干净 clone 到本地验收 / 性能基准可复现** 的完整步骤。
> 环境实测于 2026-10：Windows 11 + Node 24 + Docker Desktop（seekdb 1.4.0 容器）+ NVIDIA Lovelace（WebGPU 可用）。
> 本文与 `docs/benchmarks/README.md`、`docs/验收自检.md` 配套；所有命令在 2026-10 实测通过。

## 0. 一键最短路径

```bash
# ① 依赖（根 + 三个子包）
npm run install:all

# ② 配置（全部可选，.env / web/.env.local 均已被 gitignore）
cp .env.example .env                        # PowerShell: Copy-Item .env.example .env
cp web/.env.local.example web/.env.local    # PowerShell: Copy-Item web/.env.local.example web/.env.local

# ③ 启动 seekdb（Docker；宿主机 2882）
npm run db:up
docker compose ps                           # 等待 seekdb 变 healthy

# ④ 准备前端静态资产：ORT wasm（同源 /ort/）+ q8/fp16 模型（首次需网络）
npm run prepare:assets

# ⑤ 启动 dev（Docker 模式会读取 .env 的 SEEKDB_*）
npm run dev:docker
#   浏览器打开 http://localhost:5173 ；API http://localhost:3001/api/health

# ⑥ 自检（另开终端）
npm run acceptance                           # PASS/FAIL 表；退出码 0 表示可用
```

## 1. 前置条件

| 依赖 | 要求 | 说明 |
|---|---|---|
| Node.js | ≥ 18.17（CI 用 22，实测 24 可用） | `npm run acceptance` 会校验 |
| npm | ≥ 9（随 Node 提供） | 四个 package（根/server/web/scripts）各自锁版本 |
| Docker Desktop / docker compose | 任意近期版本（实测 Engine 29、Compose v5） | 方式 A：容器化 seekdb（推荐） |
| seekdb | 1.4.0（容器）或 Windows MSI（1.3.0+）或 Linux/macOS 嵌入式 | 三选一，见下 |
| 浏览器 | Chrome / Edge / Chromium（WebGPU 需硬件支持） | `bench-browser` 自动探测；也可 `BROWSER_PATH` |

系统盘占用：所有模型、ORT 资源、浏览器基准临时文件都应放在工作区或数据盘，仓库内仅保存**锁文件与报告**。

## 2. seekdb 启动方式（三选一）

### 方式 A：Docker Compose（推荐）

`docker-compose.yml` 固定服务名 `seekdb`，镜像 `quay.io/oceanbase/seekdb:latest`，并把数据卷挂到容器内 `/var/lib/seekdb`：

- 实测镜像：seekdb **1.4.0**，digest `sha256:4db4961869d554313520d6081fca29265ba6da6db7313311bd8acbed771a956b`（与 seekdb-js 1.3.0 客户端兼容）。
- 端口：`${SEEKDB_PORT:-2882}:2881`。容器内固定 2881，宿主机默认 2882 以免与本机其它 seekdb 冲突。
- 需要完全 pin 住版本时，把 `SEEKDB_IMAGE` 改成 `quay.io/oceanbase/seekdb@sha256:4db49618…`。
- healthcheck：`mysqladmin ping -h127.0.0.1 -P2881 -uroot`，`restart: unless-stopped`。

```bash
npm run db:up        # docker compose up -d seekdb
docker compose ps    # STATUS 列应为 healthy
npm run db:down      # 停止（保留数据卷 seekvec_seekdb-data）
```

`.env` 中设置 `SEEKDB_PORT=2882` 后，`npm run dev:docker` 会自动把它注入 server 进程（系统环境变量优先于 `.env`）。

### 方式 B：Windows MSI

1. 从 <https://github.com/oceanbase/seekdb/releases> 下载 MSI；
2. 管理员 PowerShell：

```powershell
cd "C:\Program Files\seekdb\bin"
.\seekdb_manage.ps1 install
.\seekdb_manage.ps1 start
Test-NetConnection 127.0.0.1 -Port 2881
```

3. `.env` 里 `SEEKDB_PORT=2881`，然后 `npm run dev`（不需要 Docker 检查）。

### 方式 C：Linux/macOS 嵌入式

```bash
export SEEKDB_PATH=/path/to/seekdb-data   # 设置后忽略 HOST/PORT
npm run dev
```

> Windows 官方不支持嵌入式模式，请勿在 Windows 设置 `SEEKDB_PATH`。

## 3. 环境变量

- 根 `.env`（server + Node 脚本 + docker compose）：完整清单与注释见 `.env.example`。`npm run dev`、`acceptance`、`probe` 会自动读取根 `.env`（系统环境变量优先）。
  关键项：`SEEKDB_HOST/PORT/USER/PASSWORD/DATABASE`、`PORT`、`CORS_ORIGINS`、`SEEKDB_QUERY_TIMEOUT_MS=30000`、`SEEKDB_IMAGE`、`SEEKVEC_CACHE_DIR`、`HF_ENDPOINT`、`BROWSER_PATH`、`SEEKVEC_BASE_URL`。
- `web/.env.local`（浏览器构建期变量，Vite 只读 web/ 目录）：见 `web/.env.local.example`。示例默认启用“本地模型 + 同源 ORT”，需先执行 `npm run prepare:assets`；若删除 `VITE_LOCAL_MODELS=1`，模型将从 HF 在线加载。
  关键项：`VITE_HF_ENDPOINT`、`VITE_ORT_WASM_PATH`、`VITE_LOCAL_MODELS`、`VITE_LOCAL_MODEL_PATH`。

修改 `web/.env.local` 后需要重启 dev server 才生效。

## 4. 模型资产（可复现的模型锁定）

`models.lock.json` 固定了两个 embedding 模型的 revision、文件清单、大小与 sha256（由 `scripts/fetch-models.mjs` 生成/校验）：

| 模型 | 角色 | id | revision | dim |
|---|---|---|---|---|
| bge-small-zh-v1.5 | `text_zh`（默认） | `Xenova/bge-small-zh-v1.5` | `75c43b069aac4d136ba6bc1122f995fedcfd2781` | 512 |
| all-MiniLM-L6-v2 | `text_en` | `Xenova/all-MiniLM-L6-v2` | `751bff37182d3f1213fa05d7196b954e230abad9` | 384 |

每个模型 7 个文件：`config.json`、`tokenizer.json`、`tokenizer_config.json`、`special_tokens_map.json`、`onnx/model_quantized.onnx`(q8)、`onnx/model_fp16.onnx`(fp16)、`onnx/model.onnx`(fp32)；合计 14 文件 / **326,171,082 字节（311.06 MB）**。完整 sha256 见 `models.lock.json`。

```bash
# 只生成/刷新锁文件（不联网）
node scripts/fetch-models.mjs --lock-only

# 只校验本地已下载文件（大小 + sha256；断网可用）
node scripts/fetch-models.mjs --verify

# 准备资产（默认 q8；prepare:assets = q8 + fp16）
node scripts/fetch-models.mjs --dtype q8,fp16
node scripts/fetch-models.mjs --dtype all --out web/public/models

# 国内网络：镜像源
HF_ENDPOINT=https://hf-mirror.com/ node scripts/fetch-models.mjs --dtype q8,fp16
```

行为约定：

- **本地优先**：目标目录已有文件且大小/sha256 与锁文件一致时跳过下载；不一致才重下（`--force` 强制重下）。
- 下载走 `<endpoint>/<model id>/resolve/<revision>/<file>`，先写 `.part` 再原子改名，下载后 **sha256 强校验**，失败非零退出。
- 目录布局与 Transformers.js 本地模型约定一致：`web/public/models/Xenova/<model>/…`，页面侧 `VITE_LOCAL_MODEL_PATH=/models/`。
- `web/public/models/` 已被 `.gitignore` 忽略；大文件不入库，只提交 `models.lock.json`。

## 5. 前端静态资产

```bash
npm run prepare:assets   # = node scripts/fetch-ort.mjs && node scripts/fetch-models.mjs --dtype q8,fp16
```

- `scripts/fetch-ort.mjs` 从 `web/node_modules/onnxruntime-web/dist` 复制 4 个 wasm 文件到 `web/public/ort/`（已被 gitignore）。前端默认即从同源 `/ort/` 加载（构建期未设置 `VITE_ORT_WASM_PATH` 时）；如改回 CDN 可显式设置该变量。
- `prepare:assets` 默认只取运行时需要的 q8/fp16；若复现 fp32 质量/性能基线，额外执行 `node scripts/fetch-models.mjs --dtype fp32`（或 `--dtype all`）。
- 离线数据/模型路径：`VITE_LOCAL_MODELS=1` + `VITE_LOCAL_MODEL_PATH=/models/`。

## 6. 自检与 CI

```bash
npm run check:compliance   # 合规：推理只在 web 端；server 无 onnx/transformers/default-embed 依赖与字样
npm run acceptance         # Node 版本、server/seekdb 端口、/api/health、/api/collections、模型 lock、compliance
npm run typecheck:scripts  # scripts/ 的 TS（bench.ts / eval-quality.ts / lib / tests）类型检查
npm run test:scripts       # scripts 单测（vitest）
npm test                   # server + web + scripts 单测
npm run build              # server tsc + web vite build
```

- `acceptance` 只读（GET），失败项会打印具体原因并以退出码 1 结束；`--json` 可机读，`--base-url` 可指向非默认端口。
- CI（`.github/workflows/ci.yml`）在安装/构建/单测（`npm test` 含 server+web+scripts）之后追加 `npm run test:scripts`、`npm run typecheck:scripts` 与 `npm run check:compliance`，**不跑浏览器与数据库**。

## 7. 性能与质量评测

```bash
# 浏览器基准（真实应用链路；默认读取 data/perf/corpus 与 data/perf/queries.txt）
npm run bench:browser -- --backend wasm --dtype q8 --runs 5 --warmup 1
npm run bench:browser -- --check        # 只做环境自检（浏览器/页面/语料），不启动基准
npm run bench:browser -- --smoke        # 冒烟：1 次导入 + 1 条查询

# 矩阵（读取 docs/benchmarks/matrix.json，默认 ABBA 双向、聚合中位数/IQR）
npm run bench:matrix
npm run bench:matrix -- --dry-run       # 打印将执行的命令
npm run bench:matrix -- --only fp32-wasm,q8-wasm

# Node 端质量回归（Recall@k / nDCG / MRR；fp32 vs q8/fp16）
npm run eval:quality
```

输出位置与汇总口径见 `docs/benchmarks/README.md`；原始数据提交到 `docs/benchmarks/<run>/`。

## 8. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `npm run dev` 报 seekdb 未就绪 | 先 `npm run db:up`，等 `docker compose ps` healthy；或确认 `.env` 的 `SEEKDB_PORT` 与容器映射一致（默认 2882）。 |
| `npm run db:up` 报容器名冲突 | 本机之前用 `docker run --name seekvec-seekdb` 手工建过同名容器：`docker rm -f seekvec-seekdb` 后由 compose 接管（数据在卷 `seekvec_seekdb-data` 中不会丢），或继续用旧容器、不执行 db:up。 |
| `Can't add new command when connection is in closed state` | seekdb 容器重启后 server 旧连接失效：重启 dev server（`Ctrl+C` 后重跑）。 |
| 模型下载失败 / 很慢 | `HF_ENDPOINT=https://hf-mirror.com/`；或提前 `node scripts/fetch-models.mjs` 后设 `VITE_LOCAL_MODELS=1` 离线使用。 |
| `--verify` 报 sha256 不匹配 | 文件损坏/半截：重新 `node scripts/fetch-models.mjs --force --dtype <对应精度>`。 |
| 页面徽标显示 WASM 或降级 | 浏览器/驱动不支持 WebGPU（或未在 localhost/HTTPS 安全上下文）；浏览器基准须避免 `--disable-gpu`。 |
| `bench-browser` 找不到浏览器 | 安装 Chrome/Edge，或设置 `BROWSER_PATH`（见 `.env.example`）；脚本会探测 Playwright 缓存，不写死用户名。 |
| `bench-browser` 报语料不存在 | 需要 `data/perf/corpus/` 与 `data/perf/queries.txt`（数据工作流生成），或用 `--corpus/--queries` 指定。 |
| 端口 5173/3001 被占用 | Vite/server 修改端口后，用 `--base-url` 指到实际页面地址。 |

## 9. 干净环境复现清单（checklist）

1. `git clone` → `npm run install:all`
2. `cp .env.example .env`、`cp web/.env.local.example web/.env.local`（按需改端口/镜像）
3. `npm run db:up` → `docker compose ps` 等 healthy
4. `npm run prepare:assets`（或已有模型时 `node scripts/fetch-models.mjs --verify`）
5. `npm run dev:docker`
6. `npm run acceptance` → 全 PASS
7. `npm run eval:quality`（Node 质量回归）与 `npm run eval:quality:browser`（浏览器实际链路质量）
8. `npm run bench:matrix`（浏览器主口径，需 `docs/benchmarks/matrix.json` 与 perf 语料）
9. 结果归档到 `docs/benchmarks/<run>/`，由 Lead 汇总进最终报告
