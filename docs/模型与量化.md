# 模型与量化说明

> 正式赛题 2.2 / 4.2 要求：开源 embedding 模型、注明来源与版本；采用 INT8/FP16 方案并说明处理方式、量化前后体积与压缩比、检索质量变化；完整源码需提供模型获取及量化步骤。

## 1. 模型与版本锁定

| 角色 | 仓库 | 上游模型 | revision（固定） | 维度 | 许可 |
|---|---|---|---|---|---|
| `text_zh`（默认） | [Xenova/bge-small-zh-v1.5](https://huggingface.co/Xenova/bge-small-zh-v1.5) | [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) | `75c43b069aac4d136ba6bc1122f995fedcfd2781` | 512 | MIT |
| `text_en` | [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2) | [sentence-transformers/all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) | `751bff37182d3f1213fa05d7196b954e230abad9` | 384 | Apache-2.0 |

- 仓库只保存锁文件 [`models.lock.json`](../models.lock.json)（revision + 每文件 sha256 + 字节数），**不提交模型权重**。
- 运行 `npm run prepare:assets`（或 `node scripts/fetch-models.mjs --dtype all`）按锁下载/校验；已存在且 sha256 匹配则跳过。
- 支持 Hugging Face 官方源或镜像：`HF_ENDPOINT=https://hf-mirror.com/`。

## 2. 量化方案与来源

本项目直接使用 **Xenova 仓库发布的 ONNX 量化产物**（社区官方转换），而非在本地重新量化：

| dtype | 实际文件 | 说明 |
|---|---|---|
| `q8`（INT8，默认 WASM） | `onnx/model_quantized.onnx` | 8-bit 权重量化（transformers.js `dtype: 'q8'`） |
| `fp16`（默认 WebGPU） | `onnx/model_fp16.onnx` | 半精度权重（`dtype: 'fp16'`） |
| `fp32`（评测基线） | `onnx/model.onnx` | 全精度权重（`dtype: 'fp32'`，仅质量/性能基线） |

- 前端在 `web/src/inference/pipeline.ts` 通过 `pipeline('feature-extraction', modelId, { dtype, device })` 加载；dtype 由后端/URL 参数决定（WASM→q8，WebGPU→fp16，可用 `?dtype=` 覆盖）。
- 所有推理均在浏览器内完成（Transformers.js + ONNX Runtime Web）；server 不导入任何推理/量化库。
- 量化方式（上游）：`optimum` 对 `bge-small-zh-v1.5` / `all-MiniLM-L6-v2` 的 ONNX 导出做动态量化（INT8）与 FP16 转换；Xenova 仓库即为该流程的公开产物，锁文件固定到具体 revision 与 sha256，保证可复现。

### 2.1 若需自行量化（可复现步骤，非本项目运行必需）

```bash
# 以 bge-small-zh-v1.5 为例（Python + optimum + onnxruntime）
pip install "optimum[exporters]" onnxruntime
optimum-cli export onnx --model BAAI/bge-small-zh-v1.5 --task feature-extraction onnx/bge-base
optimum-cli onnxruntime quantize --arm64 --avx512 --onnx_model onnx/bge-base -o onnx/bge-q8
# FP16：用 onnxconverter-common 或 optimum 的 fp16 导出；本项目直接复用 Xenova 的 q8/fp16 产物
```

> 本仓库不执行上述 Python 流程；以 `models.lock.json` 锁定的 Xenova 产物为准，避免因本地量化工具版本差异导致不可复现。

## 3. 模型体积与压缩比（实测）

按 `models.lock.json` 中每 dtype 的**全部模型文件**（config/tokenizer/special_tokens + ONNX）统计；压缩比 = fp32 总体积 / 量化后总体积。

| 模型 | fp32 | fp16 | q8（INT8） | fp32/q8 | fp32/fp16 |
|---|---|---|---|---|---|
| bge-small-zh-v1.5 | 95.29 MB | 47.94 MB | 24.45 MB | **3.90×** | 1.99× |
| all-MiniLM-L6-v2 | 91.10 MB | 46.01 MB | 23.69 MB | **3.85×** | 1.98× |

- 单 ONNX 文件口径：bge `90.46 MB → 22.90 MB`（3.95×，fp16 45.30 MB）；MiniLM `86.20 MB → 21.91 MB`（3.94×，fp16 43.20 MB）。
- 说明：赛题提示 INT8 约 12%（≈8×）通常是“纯权重”理论口径；实际 ONNX 文件还包括量化元数据等，本项目按**实测文件总体积**报告，约 3.9×（符合 int8≈fp32 的 1/4 量级）。

## 4. 检索质量变化（量化前后）

### 4.1 Node 质量回归（`npm run eval:quality`，CPU）

评测集：`data/eval`（60 篇自有中英文文档、73 chunks、60 条标注查询、229 条 chunk 级 qrels）；指标：Recall@1/3/5、nDCG@5/10、MRR（macro），rel≥1 为相关。

| 模型 | dtype | R@5 | nDCG@10 | MRR | ΔR@5 vs fp32 | ΔnDCG@10 vs fp32 | 质量门 |
|---|---|---|---|---|---|---|---|
| bge-small-zh-v1.5 | fp32（基线） | 0.5606 | 0.7549 | 0.8840 | — | — | — |
| | **q8** | **0.5682** | **0.7532** | **0.8928** | +0.76pp | −0.17pp | ✅ |
| | fp16 | 0.5606 | 0.7549 | 0.8840 | ±0 | ±0 | ✅ |
| all-MiniLM-L6-v2 | fp32（基线） | 0.4429 | 0.5884 | 0.7188 | — | — | — |
| | **q8** | **0.4443** | **0.5964** | **0.7318** | +0.14pp | +0.80pp | ✅ |
| | fp16 | 0.4429 | 0.5884 | 0.7188 | ±0 | ±0 | ✅ |

- 质量门：Recall@5 降幅 ≤2pp、nDCG@10 降幅 ≤0.02；4/4 量化对比通过。
- fp16 在 Node CPU 上被 ONNX Runtime 上采样为 fp32 计算，因此 Node 侧 fp16 与 fp32 完全一致；**WebGPU 的 fp16 真实行为以浏览器评测为准**（见性能与质量报告）。
- 原始数据：`docs/benchmarks/eval-quality/raw.json`、`summary.md`。

### 4.2 浏览器端（实际应用链路）

`scripts/eval-quality-browser.mjs` 在真实应用页面（`?perf=1`）中通过 `window.__seekvecEval` 完成同一评测集的导入与检索：浏览器真实分块 → 端侧推理 → HTTP 写入 seekdb → 查询向量化 → seekdb 检索（含 HNSW 近似与 hybrid RRF），按 metadata `{source, chunkIndex}` 对齐 chunk 级 qrels。

| 配置（请求/实际） | 模型 | ingest | Recall@5 | nDCG@10 | MRR | ΔR@5 vs fp32 | ΔnDCG@10 vs fp32 |
|---|---|---|---|---|---|---|---|
| fp32 + WASM（基线，actual wasm/fp32） | bge-small-zh-v1.5 | 73 chunks / 5.9s | 0.5642 | 0.7651 | 0.8868 | — | — |
| **q8 + WASM（INT8，actual wasm/q8）** | 同上 | 73 / 6.7s | **0.5592** | **0.7619** | 0.8992 | **−0.50pp** | **−0.0032** |
| **fp16 + WebGPU（actual webgpu/fp16，NVIDIA Lovelace，无降级）** | 同上 | 73 / 6.6s | **0.5642** | **0.7652** | 0.8868 | 0.00pp | +0.0001 |

- 质量门（Recall@5 降幅 ≤2pp、nDCG@10 降幅 ≤0.02）：浏览器链路 **3/3 通过**（q8 −0.50pp/−0.0032）。
- 与 Node 口径的差异来源：浏览器链路包含 seekdb HNSW 近似检索与 hybrid RRF（20 条查询带 keyword），Node 口径为精确余弦排序；两套数据互补、不混用。
- 原始数据：`docs/benchmarks/quality-browser/{summary.md,raw.json}` 及三组子目录。

## 5. 复现命令

```bash
# 下载/校验模型（本地模型目录位于 web/public/models，不入库）
npm run prepare:assets
node scripts/fetch-models.mjs --dtype all --verify

# 量化前体积与压缩比 + q8/fp16 一致性
npm run bench

# 标注评测集上的检索质量（fp32 vs q8 vs fp16）
npm run eval:quality
npm run eval:quality -- --out docs/benchmarks/eval-quality

# 浏览器端质量（实际应用链路，需 dev server + seekdb 运行）
npm run eval:quality:browser -- --out docs/benchmarks/quality-browser
```

## 6. 限制与说明

- 评测集为项目自建（`data/eval`），60 条查询、单标注人；结论用于“量化前后不明显掉点”的相对比较，不代表通用 benchmark 绝对水平。
- 分块参数（256 字符 / 32 overlap / 最短 10）与 qrels 的 chunkIndex 强耦合；如修改 `web/src/inference/chunk.ts` 默认值，必须重跑 `npx tsx data/eval/generate.ts` 并更新 qrels。
- 模型许可证与引用信息见 [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md)。
