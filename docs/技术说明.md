## 1. 模型与量化

| 模型 | 来源 / revision | 维度 | 量化 | 模型总体积 | 压缩比 | 许可 |
|---|---|---|---|---|---|---|
| bge-small-zh-v1.5（默认） | [Xenova/bge-small-zh-v1.5](https://huggingface.co/Xenova/bge-small-zh-v1.5) @ `75c43b06…` | 512 | INT8(q8) / FP16 / FP32 | q8 **24.45 MB** / fp16 47.94 MB / fp32 95.29 MB | **3.90×**（fp32/q8） | MIT |
| all-MiniLM-L6-v2（英文） | [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2) @ `751bff37…` | 384 | 同上 | q8 23.69 MB / fp16 46.01 MB / fp32 91.10 MB | 3.85× | Apache-2.0 |

- 采用 Xenova 发布的 ONNX 预量化产物（INT8/FP16/FP32），`models.lock.json` 固定 revision + 每文件 sha256，`scripts/fetch-models.mjs` 按锁下载/校验；仓库不提交模型权重。
- 浏览器端 `pipeline('feature-extraction', model, { dtype, device })` 加载：WASM→q8，WebGPU→fp16，可用 `?dtype=` 覆盖；`pooling:'mean' + normalize:true`。
- 质量（同一标注集：60 文档/73 chunks/60 查询/229 qrels；Rel≥1 为相关）：
  - Node 精确余弦：bge q8 vs fp32 **ΔR@5 +0.76pp / ΔnDCG@10 −0.17pp**；MiniLM q8 +0.14pp/+0.80pp；4/4 通过质量门。
  - 浏览器实际链路（seekdb HNSW+RRF）：q8+WASM vs fp32+WASM **ΔR@5 −0.50pp / ΔnDCG@10 −0.0032**；fp16+WebGPU 与 fp32 持平；**3/3 通过**。
- 质量门：Recall@5 降幅 ≤2pp、nDCG@10 降幅 ≤0.02。详表：[模型与量化.md](模型与量化.md)、[性能与质量报告 §5](性能与质量报告.md)。

## 2. 端侧运行（浏览器内推理）

```
启动 → 读取 URL/localStorage 配置 → detectBackend()
  ├─ WebGPU 可用 → pipeline(device:'webgpu', dtype:'fp16')
  ├─ 不可用/初始化失败 → WASM(q8) 并显示降级原因（auto 模式）
  └─ ?backend=webgpu|wasm 强制模式：失败显示红错，不静默降级（保证评测口径）
        ▼
inference/runtime.ts 单例（key=modelKey:backend:dtype）
  ├─ 共享给导入/检索/评测；reload 全局生效；generation 防切模型竞态
  ├─ progress_callback 拆分 model.download / model.init / model.total；cold/warm 标记
  └─ ORT wasm 同源 `/ort/`（prepare:assets 生成），COOP/COEP 启用 SharedArrayBuffer
```

- **实测**（Chromium 153，NVIDIA Lovelace，localhost 安全上下文）：`webgpu/fp16` 实际后端确认无降级；`wasm/q8` 强制路径正常；auto 无 WebGPU 时正确降级并给出原因。
- 冷/热：q8+WASM 冷启动 model.total **722 ms**（下载 359 + 初始化 357）；预热加载约 **0.6–0.7 s**；fp16+WebGPU 约 1.05 s（本地静态模型资源口径，公网下载另计）。
- 查询向量化：q8+WASM **9.0 ms**、fp16+WebGPU **13.9 ms**；文档批向量化吞吐 fp16+WebGPU **202 chunks/s** vs q8+WASM **28.4 chunks/s**、fp32+WASM 18.4 chunks/s。
- UI：`BackendBadge` 显示当前后端、强制/降级原因、模型加载耗时；模型加载失败为红色错误态并提供重试；`?perf=1` 时检索面板展示向量化/检索/端到端耗时。

## 3. SeekDB 使用

| 集合 | Schema |
|---|---|
| `kb_text_zh`（默认） | `VectorIndexConfig(HNSW, dim=512, cosine)` + `FulltextIndexConfig('ik', smart)` |
| `kb_text_en` | `VectorIndexConfig(HNSW, dim=384, cosine)` + `FulltextIndexConfig('ik', smart)` |
| `kb_image`（v1.1 预留） | 仅 HNSW，未启用 |

- `embeddingFunction: null`：向量全部由浏览器推理写入；server 不导入任何推理库（`npm run check:compliance` 审计）。
- **混合检索在库内完成**：`collection.hybridSearch({ query:{whereDocument:{$contains}}, knn:{queryEmbeddings,nResults}, nResults })`，RRF 由 seekdb `DBMS_HYBRID_SEARCH` 合并；业务侧只取最终 top-k，不做客户端拼合。纯向量走 `collection.query()` 返回 distances；server 按 `scores|distances` 语义分别返回。
- **索引刷新**：导入中间批次 `refreshIndex=false`，仅最后一批刷新一次；失败可调用 `POST /api/collections/:name/refresh` 补偿。文档支持 `mode=insert`（首批快速写入）与 `mode=upsert`（幂等重导）。
- **一致性**：确定性 chunk id（source+chunkIndex+text 的 FNV 哈希）→ 重复导入幂等；文件变短/改名时按 `source` 对比旧 id 清理陈旧块并刷新。
- **可观测**：`POST /api/search` 返回 `{mode,timings{resolveMs,dbMs,totalMs},knnK}`；`POST /api/documents` 返回 `{mode,refreshed,timings{upsertMs,refreshMs,totalMs}}`；`GET /api/health` 返回真实 server 版本、连接延迟、`refreshIndexSupported`。
- **鲁棒性**：seekdb 重启自动重连重试一次；查询超时 `SEEKDB_QUERY_TIMEOUT_MS`；hybrid 调用 FIFO 串行化规避会话变量串扰；keyword 做 query_string 转义；入参统一校验（400/404/409/503）。
- 实测 seekdb 检索延迟 **2.2–2.7 ms**（server timings，HNSW + 全文/RRF），端到端主要成本在浏览器与 HTTP。

## 4. 状态管理与优化

**状态**：Zustand `modelStore`（当前模型/维度，persist）、`backendStore`（实际/强制后端、原因、模型加载、错误）、`kbStore`（集合清单、activeCollection，persist、导入进度/计数）、`searchStore`（query/keyword/结果/错误）。推理侧 `inference/runtime.ts` 单例共享加载状态；`perf/metrics.ts` 独立观测域（仅 `?perf=1` 开启）。启动时 `GET /api/collections` 回填并恢复 activeCollection → 刷新后直接可检索；集合不存在/维度不符时明确提示并回退约定集合。

**优化点与前后实测**（同机、同语料 120 chunks、ABBA×5 轮中位数；详见[性能与质量报告 §6](性能与质量报告.md)）：

| 优化 | 优化前 | 优化后 | 收益 |
|---|---|---|---|
| 批处理（embedding+写入） | batch=1 导入 9.30 s，写入 3.02 s | batch=16 导入 6.93 s，写入 0.92 s | **导入 −25.5%**，网络写入开销 −70% |
| 索引刷新策略 | refresh=each 导入 11.42 s（8 次刷新 4.77 s） | refresh=last 导入 6.93 s（1 次 0.56 s） | **导入 −39.3%**，刷新开销 −88% |
| INT8 量化（WASM） | fp32 导入 9.47 s，模型 95.29 MB | q8 导入 6.93 s，模型 24.45 MB | 导入 −26.8%，吞吐 +54%，体积 3.90×；质量 −0.50pp R@5 |
| WebGPU+FP16 | q8+WASM 导入 6.93 s，向量化 28.4 chunks/s | fp16+WebGPU 导入 3.38 s，向量化 202.4 chunks/s | 导入 **−51.3%**、向量化时间 **−86%**；小查询 e2e +25%（导入主导场景更优） |
| 幂等导入 | 重复导入产生重复分块 | 确定性 ID + upsert，条目数不变 | 重导幂等（e2e 验证） |
| 陈旧块清理 | 文件变短后旧 chunk 残留 | 按 source 清理 + 补偿刷新 | 检索结果与当前知识库一致 |
| 连接自愈 | seekdb 重启后 500 | 自动重连重试 | 无需重启 dev |

- 查询链路拆分：`query.embed` 8.9–13.9 ms + `query.http` 13.5–15.1 ms + `db.search` 2.2–2.7 ms + 渲染 ≈ 端到端 **28–36 ms**（p50）。
- 基准中一致性防护（按 source 清理）额外占导入约 1.4–1.6 s；后续可合并清理请求、按变更触发以进一步优化。

## 6. 交付与复现

```bash
npm run install:all
cp .env.example .env          # PowerShell: Copy-Item .env.example .env
npm run db:up                 # Docker seekdb 1.4.0（数据卷 /var/lib/seekdb）
npm run prepare:assets        # ORT wasm + q8/fp16 模型（models.lock.json 校验）
npm run dev:docker            # 启动 server(3001) + web(5173)
npm run acceptance            # 环境/API/模型/合规自检
```

- 浏览器打开 <http://localhost:5173>，导入 `data/demo/` 示例文档即可演示；填「关键字」走 seekdb 库内混合检索；`?backend=wasm|webgpu` 验证降级路径；`?perf=1` 查看阶段耗时。
- 可复现步骤（三平台/受限网络）、故障排查见[复现.md](复现.md)；模型获取与量化说明见[模型与量化.md](模型与量化.md)；验收证据见[验收自检.md](验收自检.md)。
