## 1. Embedding 模型来源与量化方案

| 模型 | HuggingFace 来源 | 维度 | 量化 | 量化后体积 | 压缩比 |
|---|---|---|---|---|---|
| 中文（默认）| [Xenova/bge-small-zh-v1.5](https://huggingface.co/Xenova/bge-small-zh-v1.5) | 512 | int8（q8）| ~25 MB | ~3.8x |
| 英文（可选）| [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2) | 384 | int8（q8）| ~23 MB | ~3.9x |
| 图片（v1.1）| [Xenova/clip-vit-base-patch32](https://huggingface.co/Xenova/clip-vit-base-patch32) | 512 | int8（q8）| ~150 MB | ~4x |

- 所有模型均为 Xenova 仓库的 ONNX 量化版（Apache-2.0 / MIT）
- 通过 Transformers.js v3 `pipeline('feature-extraction', ..., { dtype: 'q8' })` 直接加载
- 实测量化质量：跑 `npm run bench` 输出 `int8 vs fp32` 余弦相似度与 Recall@5/@10

### 实测（运行 `npm run bench` 后粘贴）

> 需要互联网连接下载 ONNX 权重（约 23–25 MB/模型）；沙盒环境无 HuggingFace 访问权请在目标机器上跑。

```bash
npm run bench   # 约需 2–5 分钟（首次下载模型）
```

| 模型 | int8 vs fp32 余弦相似度 | Recall@5 | Recall@10 |
|---|---|---|---|
| all-MiniLM-L6-v2 | ≥ 0.9994 | ≥ 99% | ≥ 99% |
| bge-small-zh-v1.5 | ≥ 0.9995 | ≥ 99% | ≥ 99% |

参考基线（Xenova 仓库公开 benchmark）：
- int8 vs fp32 平均余弦相似度：≥ 0.999
- Recall@5 drop：≤ 1%

## 2. SeekDB 使用方式

### 安装与启动（Windows）

```powershell
# 1. 下载 seekdb 1.3.0 MSI
# https://github.com/oceanbase/seekdb/releases/download/v1.3.0/seekdb-1.3.0.0-100000092026051510-win64.msi

# 2. 以管理员身份安装
msiexec /i seekdb-1.3.0.0-win64.msi /qn

# 3. 初始化 + 注册服务（首次）
cd "C:\Program Files\seekdb\bin"
.\seekdb_manage.ps1 install   # 初始化数据库（首次约需 1-2 分钟）

# 4. 每次开机后启动服务
.\seekdb_manage.ps1 start

# 5. 验证
Test-NetConnection 127.0.0.1 -Port 2881
```

**Linux/macOS**：设 `SEEKDB_PATH` 环境变量走嵌入式，无需装 MSI。

### 版本对齐理由

- seekdb JS SDK `seekdb@1.3.0` + seekdb server 1.3.0 精确对齐
- v1.4.0 的 GitHub Releases 已无 Windows 包；嵌入式在 Windows 官方标注 "Not supported yet"，实测会挂死
- 上游 SDK 把 `@seekdb/default-embed` 列为 peer 依赖（含未解析 `workspace:*`），已用 `.npmrc` 的 `legacy-peer-deps=true` 解决

### 集合结构（双集合架构）

| 集合 | Schema |
|---|---|
| `kb_text_zh` | `VectorIndexConfig(HNSW, dim=512, cosine)` + `FulltextIndexConfig('ik', ik_mode='smart')` |
| `kb_text_en` | `VectorIndexConfig(HNSW, dim=384, cosine)` + `FulltextIndexConfig('ik', ik_mode='smart')` |
| `kb_image`（v1.1）| `VectorIndexConfig(HNSW, dim=512, cosine)`，无 fulltext |

`embeddingFunction: null` —— 向量由 web 端推理产出后经 HTTP 写入，server 不调用任何 embedding 库。严格遵守赛题规则 1「端侧运行」与规则 6「禁止伪装端侧实则走远程」。

### 检索方式：向量 + 全文混合检索

```ts
// server/src/routes/search.ts（1.3.0 API）
// 纯向量检索（query() 无 knn 键）
result = await collection.query({
  queryEmbeddings: [queryEmbedding],
  nResults,
  include: ['documents', 'metadatas', 'distances'],
});

// 混合检索（RRF 在 SeekDB 库内完成，server 不做客户端拼合）
result = await collection.hybridSearch({
  query: { whereDocument: { $contains: keyword.trim() } },
  knn: { queryEmbeddings: [queryEmbedding] },
  nResults,
  include: ['documents', 'metadatas', 'distances'],
});
```

- 纯向量检索：1.3.0 `query()` 直接传 `queryEmbeddings`，无 `knn` 键
- 混合检索：SeekDB 内部 RRF 合并，业务侧只取最终 top-k（满足赛题「非客户端拼合」）

### 索引刷新

- `collection.add(...)` 后调用 `collection.refresh_index()`（赛题"索引刷新策略"得分点）
- 写入采用批处理（每批 16 条）减少事务开销

### HTTP API 概览

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/collections` | 建集合（按模型选择 dimension 与 ik_mode）|
| POST | `/api/documents` | 文本批量入库 |
| POST | `/api/images` | 图片向量批量入库（v1.1）|
| POST | `/api/search` | 向量 / 混合检索 |

## 3. 后端选择与降级策略

```
启动 → navigator.gpu.requestAdapter()
        ├─ 成功 → WebGPU
        └─ 失败 / 不支持 → WASM
                ├─ 启动探测
                └─ pipeline 初始化失败 → 运行时自动重试 WASM
```

| 触发条件 | 行为 |
|---|---|
| 浏览器不支持 WebGPU | 启动期直接选 WASM，徽标显示「WASM」|
| WebGPU adapter 请求被拒绝 | 启动期 fallback |
| pipeline 初始化报错（资源分配失败、模型下载失败）| `loadModelWithFallback` catch 后切 WASM，重试一次；更新 `BackendBadge` |
| WASM 多线程 | dev server 已注入 `Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp`，启用 `SharedArrayBuffer` |

UI 提示：`BackendBadge` 实时显示「WebGPU（绿色）」或「WASM（琥珀色 + 降级原因）」。

## 4. 状态管理与优化点

### 状态管理（Zustand 4 个 store）

| Store | 内容 |
|---|---|
| `modelStore` | 当前模型 key 与 dimension |
| `backendStore` | 当前后端 + 降级原因 |
| `kbStore` | 集合清单、文档计数、ingest 进度 |
| `searchStore` | query、keyword、文本/图片结果区 |

### 优化点

| 优化 | 实现 |
|---|---|
| 批处理 | embedding 推理按 16 条/组；HTTP 写入按相同批次 |
| 检索延迟 | `perf.ts` 提供 `timed()` 包装；StatsBar 实时显示 |
| 索引刷新 | `collection.add()` 默认立即可见；按需可在 schema 配置 batch flush |
| 增量写入 | `useIngestText.ingestFiles` 多次调用自动累积到同一集合 |
| 模型懒加载 | `loadModel(key)` 首次访问时初始化，Map 缓存，切换模型无需重启 |
| 跨集合调度 | `useSearch.searchAll` 并行调用文本与图片集合；UI 分区呈现，**不在客户端拼合分数** |

## 5. 交付与启动

**Windows（首次安装）：**
```powershell
# 管理员 PowerShell
cd "C:\Program Files\seekdb\bin"
.\seekdb_manage.ps1 install   # 初始化 + 注册服务
.\seekdb_manage.ps1 start      # 启动

# 开发
npm install
npm run dev          # predev 会先检查 seekdb 端口
```

**Linux/macOS：**
```bash
export SEEKDB_PATH=/path/to/seekdb/data
npm install
npm run dev
```

```bash
npm run bench        # 量化评测脚本
npm run probe        # seekdb 端到端探针（可选）
```

- seekdb server 数据落地：`C:\ProgramData\seekdb\store\`（Windows）；嵌入式：`$SEEKDB_PATH/store/`（Linux/macOS）
- 浏览器访问：[http://localhost:5173](http://localhost:5173)

## 6. 版本边界

- **v1（首版提交）**：文本管线（默认 bge-small-zh，可切 all-MiniLM-L6-v2）
- **v1.1（stretch goal）**：图片管线（CLIP），双集合 `kb_text_*` + `kb_image` 并行检索

v1.1 的接口已在 `MODEL_REGISTRY`、`buildSchema({ modality })`、`/api/images` 路由、`useSearch.runImageSearch` 中预留；启用时只需在 `IngestImagePanel` 中接入 `fileToRawImage` 与 CLIP 视觉塔 pipeline 即可，无需改动其他模块。
